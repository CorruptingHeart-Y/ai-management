四、用户故事验收标准

（一）US01 查看项目成员

1. 可以查看预置项目成员。
2. 至少展示姓名和分工。
3. 成员 id 唯一。
4. US04 的负责人选择必须来源于这里的成员列表。

（二）US04 创建并分配任务

1. 可以填写任务标题。
2. 可以填写任务描述。
3. 可以选择负责人。
4. 负责人必须对应真实项目成员。
5. 空标题应被拒绝。
6. 无效负责人应被拒绝。
7. 创建成功后任务可以查看。
8. 刷新或重新读取后任务仍然存在。

（三）US05 更新任务状态

1. 可以修改已有任务状态。
2. 支持 TODO / DOING / DONE。
3. 页面展示待办 / 进行中 / 已完成。
4. 不要求拖拽。
5. 修改后页面能够看到新状态。
6. 刷新后状态仍然保存。
7. 非法状态应被拒绝。

1. 待开发：确定 Member 数据结构（id、name、role）。

5. 待开发：保存并重新读取任务。

（三）US05 更新任务状态

1. 待开发：复用统一 Task 模型。

4. 待开发：保存状态并支持刷新后读取。
5. 待开发：拒绝非法状态并补充测试。

六、DoD

每个用户故事只有满足对应 DoD 检查项后，才能在 Sprint 结束验收时标记为 Done。当前尚未进行验收，全部保持未勾选。

1. 功能能够正常运行。
2. 达到该用户故事验收标准。
3. 有关键路径基本测试。
4. 测试实际运行通过。
5. 关键模块或函数具有必要注释。
6. AI 生成代码经过人工 diff 审查。
7. Feature 合入 develop 后仍可运行。
8. 集成测试未破坏其他 Sprint 1 功能。
9. 有运行或测试证据。
10. AI 互动记录已经保留。

1. 杨浩伟：本轮 DRI，兼任 PO、Scrum Master、集成与质量负责人；负责主持 Sprint Planning，控制 Sprint 范围，协调公共接口，进行 PR Review，负责 develop 集成、全量测试、DoD 验收，并主持 Sprint Review、Sprint Retrospective 和最终交付检查。

八、依赖关系

1. US04 依赖 US01 提供统一成员数据。
2. US05 依赖 US04 的统一 Task 模型。
3. 三个故事必须共享同一 Member / Task 数据定义。
4. 整体依赖链为：US01 → US04 → US05。

九、统一数据约定

Member 字段：id、name、role。
Task 字段：id、title、description、assigneeId、status。
其中 assigneeId 必须对应真实存在的 Member.id。
任务状态统一为 TODO、DOING、DONE，页面中文显示为“待办”“进行中”“已完成”。

十、已识别风险

1. 多分支开发导致公共数据结构不一致。
2. US04 / US05 对 Task 定义产生冲突。
3. AI 生成代码可能与现有接口不一致。
4. 时间有限导致测试和集成时间被压缩。
5. AI 互动记录可能遗漏。

以上为当前识别的风险，不代表问题已经发生。
