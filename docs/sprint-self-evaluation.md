## 八 AI专项评估

编码智能体方面，Claude Code在US04登记中承担方案、脚手架、前后端创建能力；Codex在US01中完善成员契约、加载错误边界与已有工程复用；US05概要体现AI参与状态逻辑与测试，但不能确定未记录的模型身份。其主要贡献是形成可运行原型并补全相互依赖的实现。

测试智能体方面，历史证据包含全量24项与8项浏览器检查，能够发现接口契约或刷新行为退化。US01原记录未发生功能测试失败修复，不能虚构失败来增加过程感。US04早期测试入口修复来自原登记摘要，缺少独立失败日志。

代码审查智能体方面，静态审查关注共享模型、非法输入、注释和范围，未见当前阻断问题。原两个Minor记录保留，静态状态在05c7499修复，状态枚举重复及后续异常风险仍在。AI审查可以提出具体问题，但同属自动化工具，不能给人工Review项提供独立人类确认。

AI引入的风险包括生成独立数据源、重复枚举、只覆盖正常路径以及输出看似完整但原始记录不足。使用多个角色也可能共享相同假设，因此必须以运行证据交叉检查。

人类不可替代的职责是确认产品范围、选择架构与数据约束、阅读真实diff、处理反馈并接收交付。已确认的DRI最终Demo为人工接收提供使用层证据；尚无人工diff证明就不能宣称该责任已经完成。下一Sprint应把契约、会话、人工审查和独立集成分别落实。
