二 Keep 保留有效做法

Feature 分支隔离值得保留。三个故事分别有 feature/us01-members、feature/us04-create-task、feature/us05-task-status，允许成员围绕责任范围独立开发，提交和差异可追溯。分支并不消除共享文件依赖，价值在于保留各自实现与集成选择。

develop 统一集成使最终增量可验证。US04 合入提交为442ee8e，US05合入为79948a5。集成后复用同一成员和任务数据，不把三个故事作为三个互不关联的演示项目。后续 US01 经 integration/us01-merge 检查，再通过34b3df7合入 develop，main 未被提前更新。

AI 辅助编码、测试和文档加快了原型形成。US04脚手架、US01成员边界、US05状态更新都有记录或提交可检索。各环节复用现有结构而不扩展后续产品功能，降低首轮范围失控的风险。未统计可靠人工工时，不量化 AI 的效率提升百分比。

自动化全量回归提供了集成保护。US04五项、US05四项在 US01 增强后仍被保留，成员测试从基础能力扩展到15项，全量24项均通过。dataFile 注入和临时文件使错误数据与持久化测试不依赖共享演示数据。

在 integration 分支预先验证和保存真实证据应继续执行。US01合并虽无文本冲突，仍检查成员来源、任务分配和状态持久化。TAP、浏览器JSON和桌面/手机截图说明实际运行内容，用户确认的人工 Demo 则补充最终交互验收，不用事后虚构 PR 或截图替代。

三 Stop 停止容易造成误判的做法

共享文件未经充分协调已造成真实集成问题。79948a5的合并消息列明包文件、应用入口、路由、前端和记录文件冲突；US05原分支使用独立存储和 Jest，US04 使用公共JSON层和 node:test。技术栈同属 Node.js 并不足以保证可合并。最终选择统一数据层、移植状态逻辑和合并测试入口解决问题，不能把冲突归结为不同后端语言。

停止把“后补摘要”当作“完整原始会话”。当前17条记录混合开发登记、已保存输入摘录、工具执行记录和 Git/对话追溯摘要，US05只有概要。US04登记时间与相关提交时刻也有顺序差异。这些是实际追溯限制，不能通过润色或增加虚构轮次补齐。

停止将AI审查、自动测试和人工审查合并成一种“已验收”。本轮人工代码审查已由实际参与成员确认完成，三个故事通过Review；独立历史审查日志未完整归档。今后应保存审查范围、结论、发现和版本，这项归档改进不否定本轮已完成的审查事实。

数据契约和接口异常确认仍不够前置。当前成员、负责人、任务和状态已统一，但共享状态枚举仍在领域层、路由和前端重复；创建和更新的网络异常处理、JSON 文件写入失败与并发一致性也缺少专项覆盖。后三项是静态审查识别的风险，未在本轮复跑中复现故障，不写成已经发生的事故。

四 Start 将验证与记录前移

下一轮计划时先列出公共 Member、Task 字段，确认 API 请求、响应、非法输入和加载失败的行为，指定共享文件协调人，再拆分 Feature。这样在涉及登录、权限和新增任务字段时有统一落点。

在 AI 交互发生时保存原始输入、输出、工具与时间，摘要保留但标明来源。每个 Feature 完成后按真实 diff 进行人工 Review，记录范围、发现、处置和版本，避免直到交付才发现证据无法还原。

由杨浩伟以SM职责在Review前安排独立集成阶段，先在integration分支执行全量测试与完整链路检查。自动接口测试、浏览器操作、人工Demo和人工代码审查分别归档，演示数据与测试数据隔离；集成阶段以全量回归及链路验证完成为结束条件。

US05现有概要和源分支证明 AI 参与状态逻辑、接口和测试；工具型号和细粒度会话缺失，不能补写具体模型、逐轮提示或原始响应。原分支 Jest 用例与集成后4项 node:test口径不同，最终验收采用集成后测试，不相加成更多“通过用例”。

七 三条改进措施

以下三项改进措施是团队在本次Retrospective共同讨论确定的，由杨浩伟以PO、SM职责统筹，按下一Sprint对应阶段实施。

措施一 先统一公共契约再并行开发

问题：共享文件和独立存储导致 US04/US05真实冲突，后续权限与任务字段扩展会再次触碰公共模型。

措施：建立简明字段与接口契约，列出成功、非法输入、读写失败和前端禁用行为；指定共享数据层、路由和页面的协调人，Feature变更先核对契约。

责任人：朱传玺负责技术契约，杨浩伟协调跨分支变更。

落实阶段：下一 Sprint 计划阶段及各 Feature 编码前。

预期效果：减少重复数据源、接口偏差和共享文件返工，使不同故事可以直接组合。

措施二 同步保存AI与人工审查证据

问题：原始AI会话不完整，人工审查的独立历史日志未完整归档。

措施：交互当日保存原始会话并标注时间、成员、工具；合并前记录人工diff范围、发现、处置和提交号，摘要与原文分开。不得倒签本轮历史审查。

责任人：何健翔协调日志，各故事负责人保存原始会话，杨浩伟落实人工审查记录。

落实阶段：下一 Sprint 每次交互时及每个 Feature 合并前。

预期效果：让AI贡献、错误修复和人类决策可追溯，减少把自动通过等同全DoD的误判。

措施三 预留集成窗口并补异常覆盖

问题：多分支公共文件改动需集中验证，文件存储与前端网络失败还有未覆盖风险。

措施：在Review前保留integration验证阶段，继续隔离测试数据，补创建/状态更新网络异常、文件写入失败和重复写入一致性的测试或明确范围限制；分别归档测试、人工Demo与人工审查。

责任人：杨浩伟协调集成，彭佳成协助业务链路验收，各故事负责人补相应测试。

落实阶段：下一 Sprint 集成阶段与 Review 前。

预期效果：在进入验收前暴露跨故事退化与异常提示问题，避免污染演示数据。
