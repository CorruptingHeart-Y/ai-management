查看项目成员 → 创建并分配任务 → 更新任务状态

## 4. 用户故事验收标准

### US01 查看项目成员

- [ ] 可以查看预置项目成员；
- [ ] 至少展示姓名和分工；
- [ ] 成员 id 唯一；
- [ ] US04 的负责人选择必须来源于这里的成员列表。

### US04 创建并分配任务

- [ ] 可以填写任务标题；
- [ ] 可以填写任务描述；
- [ ] 可以选择负责人；
- [ ] 负责人必须对应真实项目成员；
- [ ] 空标题应被拒绝；
- [ ] 无效负责人应被拒绝；
- [ ] 创建成功后任务可以查看；
- [ ] 刷新或重新读取后任务仍然存在。

### US05 更新任务状态

- [ ] 可以修改已有任务状态；
- [ ] 支持 TODO / DOING / DONE；
- [ ] 页面展示待办 / 进行中 / 已完成；
- [ ] 不要求拖拽；
- [ ] 修改后页面能够看到新状态；
- [ ] 刷新后状态仍然保存；
- [ ] 非法状态应被拒绝。

## 8. 依赖关系

- US04 依赖 US01 提供统一成员数据；
- US05 依赖 US04 的统一 Task 模型；
- 三个故事必须共享同一 Member / Task 数据定义；
- 整体依赖链为：US01 → US04 → US05。

## 9. 统一数据约定

### Member

`id`、`name`、`role`

### Task

`id`、`title`、`description`、`assigneeId`、`status`

其中 `assigneeId` 必须对应真实存在的 `Member.id`。

任务状态统一为 `TODO`、`DOING`、`DONE`，页面中文显示为“待办”“进行中”“已完成”。

## 10. 已识别风险

- 多分支开发导致公共数据结构不一致；
- US04 / US05 对 Task 定义产生冲突；
- AI 生成代码可能与现有接口不一致；
- 时间有限导致测试和集成时间被压缩；
- AI 互动记录可能遗漏。

以上为当前识别的风险，不代表问题已经发生。
