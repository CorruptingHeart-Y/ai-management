## 成员数据约定

`Member` 的类型说明与校验位于 `src/domain/member.js`。每条成员记录必须包含唯一正安全整数 `id`、非空字符串 `name` 和 `role`。空成员数组合法。

| id | 姓名 | role |
|---|---|---|
| 1 | 彭佳成 | 产品与范围负责人 |
| 2 | 朱传玺 | 技术与架构负责人 |
| 3 | 杨浩伟 | 质量与风险负责人 |
| 4 | 何健翔 | AI协调与记录负责人 |

姓名、编号和分工沿用实验一《第7组 团队组建与DRI轮值表》。`role` 是长期团队分工，不表示权限；本轮 DRI 轮值不改变成员 id 或历史任务的 `assigneeId`。

运行时唯一数据源是 `data/db.json` 的 `members` 数组。`src/db.js` 中的预置成员只用于文件首次缺失时初始化；测试核对其与版本库初始数据一致。已有文件不会被 GET 接口覆盖。保留原数据层“缺少成员字段视为空列表”的兼容行为。

## 成员接口

`GET /api/members` 返回 `200 application/json`，响应为数组本身，不增加外层包装，以保持 US04 兼容。响应设置 `Cache-Control: no-store`。

```json
[
  { "id": 1, "name": "彭佳成", "role": "产品与范围负责人" },
  { "id": 2, "name": "朱传玺", "role": "技术与架构负责人" },
  { "id": 3, "name": "杨浩伟", "role": "质量与风险负责人" },
  { "id": 4, "name": "何健翔", "role": "AI协调与记录负责人" }
]
```

没有成员时返回 `[]`。数组内记录字段无效或 id 重复时返回 `500` 和 `{"error":"成员数据格式错误，请检查项目数据文件"}`。文件无法读取或 JSON 损坏时返回 `500` 和 `{"error":"成员列表暂时无法读取，请稍后重试"}`，不回退成另一份成员假数据。

US04 使用 `GET /api/members` 返回的 `id` 作为 `assigneeId`。前端列表和下拉框由同一个响应生成，提交时转换为数字；现有后端按当前 `db.readData().members` 校验负责人，不接受不存在的 id。不要在创建任务模块另写一套姓名或成员常量。

```json
{ "title": "US01 验收演示", "description": "确认成员数据一致", "assigneeId": 1 }
```

上例提交到既有的 `POST /api/tasks`。其 `201` 响应中的 `assigneeId` 为 `1`、初始 `status` 为 `TODO`。

## 页面行为

- 加载中显示提示，并禁用负责人选择与创建按钮。
- 成功时展示姓名和分工，同时生成四个负责人选项；成员信息通过 `textContent` 写入，特殊字符按普通文本显示。
- 空列表显示“暂无项目成员”，禁止提交并提供重新加载按钮。
- 成员请求失败显示错误和重新加载按钮；恢复后重新读取同一个接口。
- 任务请求失败单独提示，不覆盖已经成功加载的成员。
- 手机窄屏下成员姓名和分工可换行。

## 评审演示步骤

1. 打开页面，对照上表展示四名成员姓名及分工。
2. 打开创建任务的负责人列表，确认名单与项目成员完全一致。
3. 选择彭佳成，创建一个带唯一标题的演示任务，确认显示负责人。
4. 刷新页面，确认成员和任务负责人保持一致。
5. 使用已集成的 US05 将任务从待办改为进行中，再改为已完成；刷新确认状态保留。
6. 说明“已完成”是用户更新的任务状态，不能代替软件人工审查或 DoD 验收。

演示会创建持久化数据。需要独立演示数据时，可在 PowerShell 启动前将 `DATA_FILE` 设置为临时 JSON 路径；不要手工覆盖团队已有任务数据。
