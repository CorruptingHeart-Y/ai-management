# 爱管理用户手册（Sprint 3 集成候选）

原稿：何健翔；2026-10-23 集成核对更新，待团队审定。尚未正式发布 v1.0.0。

## 启动与数据保护

安装 Node.js 18 以上（CI 验证 Node 22/24），在项目目录运行：

```text
npm ci
npm test
npm start
```

默认打开 http://localhost:3000/；统计页 /stats.html，筛选/逾期页 /task-filters.html，首页有入口。无前端编译步骤。

真实数据默认 data/db.json；先备份，不用测试数据覆盖。演示需要独立文件时在 PowerShell 设置 `$env:DATA_FILE='D:\demo\db.json'`，确认该路径属于自己的演示目录后再运行 npm start。改端口使用 `$env:PORT='3001'`。测试始终使用临时文件，不需要改真实数据。

## 登录与角色

在首页右上角登录，演示凭证由 DRI 在版本库外提供。登录后显示角色；登出立即撤销当前会话。正常刷新会恢复当前会话，**服务重启**或角色改变后需要重新登录。网络故障会显示错误，不等于密码错误。

| 操作 | 普通成员 | 管理员 |
| --- | --- | --- |
| 查看成员/任务/统计、筛选与查看逾期 | 可以 | 可以 |
| 更新任务状态 | 可以 | 可以 |
| 创建并分配任务 | 不可以 | 可以 |
| 查看账号列表、修改角色 | 不可以 | 可以 |

角色管理在管理员首页显示；不能移除最后一名管理员。角色实际变化会撤销目标账号全部已有会话。没有独立审计日志功能，不承诺所有操作已记录。

## 创建与状态

管理员填写标题（必填）、描述（选填）、负责人（必填），选择优先级（默认中）、截止日和预置迭代（均选填），点击创建。新任务为待办；输入非法时提示错误，不保存。

管理员和普通成员都可在任务卡片切换待办/进行中/已完成。成功后刷新保留；失败时恢复原选项并提示。网络中断可能无法判断提交是否已到达服务，先刷新确认再重试。

已有任务暂不支持修改优先级/截止日/迭代，也没有删除接口。不要为修改属性盲目重复建任务，应联系 PO 记录变更需求。任务描述只是文本，不是已实现的独立验收标准字段。

## 筛选、逾期和迭代视图

从首页进入“筛选任务、查看逾期与迭代分组”：关键词搜索标题/描述，并可组合状态、优先级、负责人、迭代；重置清除筛选。“按迭代分组”显示各组任务，不等于完整迭代管理。

“仅逾期”显示截止日早于**运行服务的电脑本地今天**且未完成的任务；今天、未来、无截止日和 DONE 不计逾期。浏览器与服务位于不同时区时，以服务返回的“截至日期”为准。筛选条件保存在地址中，刷新可恢复。接口为 /api/task-query；/api/tasks 返回完整任务列表。

## 统计与异常处理

统计页展示总数、状态、优先级、负责人、迭代分布，点击刷新取最新数据。故障时清空旧统计并显示错误，不把故障显示为零任务。

| 现象 | 处理 |
| --- | --- |
| 未登录或会话失效（401） | 返回工作台重新登录 |
| 已登录但无权（403） | 核对角色，联系管理员；不能通过自改页面绕过 |
| 输入错误（400） | 根据提示核对标题、负责人、优先级、日期和迭代 |
| 网络错误 | 确认服务运行和网络连接，点击重试 |
| 数据异常（500） | 联系维护者核对数据与备份，不删除或重建真实 db.json 掩盖错误 |
| 端口占用 | 选择空闲端口再启动，不直接结束未知进程 |

边界与技术债见 [Release Notes](release-notes.md)。测试、AI 检查不能代替人工发布验收。
